    Introducció a l'API REST Darrera actualització: 23 de desembre de 2025 REST API significa Representational State Transfer API. És un tipus d'API (Application Programming Interface) que permet la comunicació entre diferents sistemes a través d'Internet. Les API REST funcionen enviant sol·licituds i rebent respostes, normalment en format JSON, entre el client i el servidor.

    11 Una sol·licitud s'envia des del client al servidor a través d'una URL web, utilitzant un dels mètodes HTTP. El servidor respon amb el recurs sol·licitat, que pot ser HTML, XML, imatge o JSON, sent JSON el format més utilitzat per als serveis web moderns. Aquests mètodes es corresponen amb operacions CRUD (Create, Read, Update, Delete) per gestionar recursos a la web. NOTA: REST és un estil de disseny arquitectònic per a les API, mentre que HTTP és el protocol de comunicació utilitzat per a la transferència de dades a través del web. Les API REST utilitzen mètodes HTTP per interactuar amb els recursos, però no són el mateix. REST defineix com s'han de comportar les API, mentre que HTTP defineix les regles per a la comunicació a través del web. Normalment funcionen juntes, però tenen finalitats diferents.

    Mètodes HTTP comuns utilitzats a l'API REST En HTTP, hi ha cinc mètodes que s'utilitzen habitualment en una arquitectura basada en REST, és a dir, POST, GET, PUT, PATCH i DELETE. Aquests corresponen a les operacions de creació, lectura, actualització i supressió (o CRUD), respectivament. Hi ha altres mètodes que s'utilitzen amb menys freqüència, com ara OPTIONS i HEAD.

    1. Mètode GET El mètode HTTP GET s'utilitza per llegir (o recuperar) una representació d'un recurs. A la ruta segura, GET retorna una representació en XML o JSON i un codi de resposta HTTP de 200 (OK). En cas d'error, sovint retorna un 404 (NOT FOUND) o 400 (BAD REQUEST).

    GET /usuaris/123 Aquesta sol·licitud obté dades per a l'usuari amb l'ID 123.

    1. Mètode POST El mètode POST s'utilitza habitualment per crear recursos nous. Sovint s'utilitza per crear recursos subordinats relacionats amb un recurs principal. Un cop creat correctament, el servidor retorna l'estat HTTP 201 (Creat) juntament amb una capçalera d'ubicació que apunta al recurs recentment creat.

    POST /usuaris { "nom": "Anjali", "correu electrònic": "gfg@example.com" } Aquesta sol·licitud crea un nou usuari amb les dades proporcionades.

    NOTA: POST no és ni segur ni idempotent.

    1. Mètode PUT PUT és un mètode HTTP que s'utilitza per actualitzar o crear un recurs al servidor. Quan s'utilitza PUT, s'envia tot el recurs al cos de la sol·licitud i substitueix el recurs actual a l'URL especificada. Si el recurs no existeix, es pot crear un de nou.

    PUT /usuaris/123 { "nom": "Anjali", "correu electrònic": "gfg@example.com" } Aquesta sol·licitud actualitza l'usuari amb l'ID 123 o crea un usuari nou si no n'existeix cap.

    1. Mètode PATCH PATCH és un mètode HTTP que s'utilitza per actualitzar parcialment un recurs al servidor. A diferència de PUT, PATCH només requereix que els camps que cal actualitzar s'enviïn al cos de la sol·licitud. Modifica parts específiques del recurs en lloc de substituir tot el recurs.

    PATCH /users/123 { "email": "new.email@example.com" } Aquesta sol·licitud només actualitza el correu electrònic de l'usuari amb l'ID 123, deixant la resta de les dades de l'usuari sense canvis.

    Diferències entre PUT i PATCH Tant PATCH com PUT s'utilitzen per actualitzar recursos al servidor, però difereixen en la manera com gestionen el procés d'actualització:

    POSAR PEGAT Substitueix tot el recurs Només actualitza els camps especificats Cal enviar les dades completes Només envia els canvis Idempotent No sempre idempotent Exemple: Actualització de tot el perfil d'un usuari Exemple: Canviar només el correu electrònic d'un usuari 5. Mètode DELETE S'utilitza per suprimir un recurs identificat per un URI. Si s'elimina correctament, retorna l'estat HTTP 200 (OK) juntament amb un cos de resposta.

    SUPRIMEIX /usuaris/123 Aquesta sol·licitud elimina l'usuari amb l'ID 123.

    Idempotència: Un mètode HTTP idempotent és un mètode HTTP que es pot cridar moltes vegades sense resultats diferents. No importa si el mètode es crida només una vegada o deu vegades. El resultat hauria de ser el mateix. De nou, això només s'aplica al resultat, no al recurs en si.

    Creació d'una API REST senzilla amb Node.js i Express Ara creem una API REST i realitzem les diverses operacions HTTP.

    Pas 1: Crea la carpeta Crea el projecte Node.js mitjançant l'ordre següent:

    mkdir aplicació-node cd aplicació-node Pas 2: Instal·leu el fitxer package.json npm init -y Pas 3: Instal·leu Express Per començar a crear una API REST a Node.js, cal instal·lar Express . Executeu l'ordre següent al terminal:

    instal·lació exprés de npm Pas 4: Crea el servidor Crea un fitxer anomenat server.js al directori arrel del projecte (node-app) i afegeix el codi següent:

    // Import the Express module const express = require('express'); const app = express(); const port = 3000;

    app.use(express.json());

    // Define a route for GET requests app.get('/users', (req, res) => { res.json({ message: 'Returning list of users' }); });

    // Define a route for POST requests app.post('/users', (req, res) => { const newUser = req.body; res.json({ message: 'User created', user: newUser }); });

    // Define a route for PUT requests app.put('/users/:id', (req, res) => { const userId = req.params.id; const updatedUser = req.body; res.json({ message: User with ID ${userId} updated, updatedUser }); });

    // Define a route for DELETE requests app.delete('/users/:id', (req, res) => { const userId = req.params.id; res.json({ message: User with ID ${userId} deleted }); });

    // Start the server app.listen(port, () => { console.log(Server is running on http://localhost:${port}); }); Pas 5: Inicieu el servidor Executeu l'ordre següent al terminal des del directori arrel del projecte:

    node server.js Si el servidor s'inicia correctament, veureu el missatge:

    El servidor s'està executant a http://localhost:3000 Sortida: Per provar l'API, obriu http://localhost:3000 a Postman o una altra eina de prova d'API.

    GET /users: Aquesta ruta obté la llista d'usuaris (o dades simulades en aquest cas). POST /users: Aquesta ruta accepta dades JSON del client per crear un usuari nou. PUT /users/:id: Aquesta ruta actualitza la informació d'un usuari en funció de l'ID d'usuari proporcionat a l'URL. DELETE /users/:id: Aquesta ruta elimina un usuari amb l'ID especificat. Característiques de les API REST Sense estat : Cada sol·licitud d'un client a un servidor ha de contenir tota la informació que el servidor necessita per complir la sol·licitud. No s'emmagatzema cap estat de sessió al servidor. Arquitectura client-servidor : les API RESTful es basen en un model client-servidor, on el client i el servidor operen de manera independent, cosa que permet l'escalabilitat. Memòria cau : Les respostes del servidor es poden marcar explícitament com a memoriacautable o no per millorar el rendiment. Interfície uniforme : les API REST segueixen un conjunt de convencions i restriccions, com ara rutes d'URL consistents, mètodes HTTP estandarditzats i codis d'estat, per garantir una comunicació fluida. Sistema per capes : les API REST es poden implementar en diverses capes, cosa que ajuda a l'escalabilitat i la seguretat. Exemple del món real d'API Rest Les API REST s'utilitzen àmpliament en diverses indústries per simplificar la comunicació entre sistemes. Algunes aplicacions comunes inclouen:

    Xarxes socials: Integració de plataformes de tercers com Facebook, Twitter i Instagram per a funcions com ara iniciar sessió, compartir i publicar. Comerç electrònic: Gestió de productes, processament de pagaments, tramitació de comandes i gestió de clients. Serveis de geolocalització : seguiment GPS, actualitzacions d'ubicació en temps real i serveis basats en la ubicació com ara trobar llocs propers. Previsió meteorològica: Obtenció de dades meteorològiques de fonts externes per proporcionar actualitzacions i previsions meteorològiques en temps real.
