    Protocol de Transferència d’Hypertext – HTTP

    Última actualització: 16 octubre 2025

    Què és HTTP?






    El protocol HTTP (Hypertext Transfer Protocol) és un protocol fonamental d’Internet, que permet la transferència de dades entre un client i un servidor. És la base de la comunicació de dades per a la World Wide Web. HTTP proporciona un estàndard perquè un navegador web i un servidor web puguin establir comunicació. És un conjunt de regles per transferir dades d’un ordinador a un altre.

    Nota: Dades com text, imatges i altres fitxers multimèdia es comparteixen al web mitjançant HTTP. Cada vegada que un usuari obre el navegador, utilitza HTTP indirectament. És un protocol d’aplicació per a sistemes d’informació distribuïts, col·laboratius i hipermèdia.

    Característiques

    • Sense estat (Stateless): Cada sol·licitud és independent i el servidor no conserva informació de les interaccions anteriors.
    • Basat en text (Text-Based): Els missatges són en text pla, llegibles i fàcils de depurar.
    • Model client-servidor (Client-Server Model): Segueix una arquitectura client-servidor per sol·licitar i servir recursos.
    • Cicle sol·licitud-resposta (Request-Response): Opera en un cicle de sol·licitud del client i resposta del servidor.
    • Mètodes de sol·licitud (Request Methods): Suporta mètodes com GET, POST, PUT, DELETE, entre d’altres, per actuar sobre recursos.

    Nota: Va ser renomenat com a Hyper-Text Transfer Protocol QUIC (HTTP/3) i desenvolupat per Google.

    Mètodes de HTTP

    • GET: Recupera dades d’un recurs específic. No hauria de tenir efectes secundaris i s’utilitza per obtenir pàgines web, imatges, etc.
    • POST: Envia dades a processar per un recurs específic. Adequat per enviaments de formularis, càrrega de fitxers i creació de nous recursos.
    • PUT: Actualitza o crea un recurs al servidor. Substitueix completament el recurs amb les dades del cos de la sol·licitud.
    • PATCH: Similar a PUT però per modificacions parcials d’un recurs. Actualitza camps específics sense substituir tot el recurs.
    • DELETE: Elimina un recurs específic del servidor.
    • HEAD: Igual que GET però només obté les capçaleres de la resposta.
    • OPTIONS: Mostra les opcions de comunicació disponibles per a un recurs.
    • TRACE: Serveix per depurar, retornant l’eco de la sol·licitud rebuda (ús limitat per seguretat).
    • CONNECT: Estableix un túnel amb el servidor a través d’un proxy HTTP (usant-se sovint amb SSL/TLS).

    Sol·licitud i Resposta HTTP






    HTTP és un protocol de sol·licitud-resposta, és a dir, per cada sol·licitud enviada per un client (normalment un navegador web), el servidor respon amb una resposta corresponent.

    1. El client envia una sol·licitud HTTP: Inclou un mètode (GET, POST, PUT, DELETE, etc.), una URI, capçaleres i opcionalment un cos.
    2. El servidor processa la sol·licitud: Recupera dades, executa scripts o altres accions.
    3. El servidor envia una resposta HTTP: Inclou un codi d’estat (200 OK, 404 Not Found, etc.), capçaleres i un cos opcional.
    4. El client processa la resposta: Mostra o gestiona el contingut rebut (pàgina HTML, imatge, dades JSON, etc.).

    Exemple de recursos sol·licitats

    Recurs sol·licitat Tipus de recurs Resposta del servidor
    Pàgina HTML HTML El servidor envia fitxer HTML
    Full d’estil (CSS) CSS El servidor envia fitxer CSS
    Imatge (JPG) Imatge (JPG) El servidor envia imatge JPG
    Codi JavaScript JavaScript (JS) El servidor envia fitxer JS
    Dades (XML/JSON) Dades El servidor envia dades XML/JSON

    El “Cercle de Sol·licituds HTTP” mostra com un navegador sol·licita diferents recursos a un servidor, i aquest li retorna els fitxers corresponents.

    Components de Sol·licitud i Resposta HTTP

    Concepte Descripció
    HTTP Request Headers Informació clau-valor enviada amb cada sol·licitud HTTP, indicant detalls com el navegador del client o les dades demanades.
    HTTP Request Body Conté les dades enviades al servidor (formularis, autenticació, etc.).
    HTTP Response Resposta del servidor amb un codi d’estat, capçaleres i cos opcional.
    HTTP Status Codes Codis de 3 dígits que indiquen el resultat de la sol·licitud: 1xx (informació), 2xx (èxit), 3xx (redirecció), 4xx (error client), 5xx (error servidor).
    HTTP Response Headers Indiquen el tipus de dades, llengua o contingut retornat pel servidor.
    HTTP Response Body Conté la informació sol·licitada (HTML, JSON, etc.).

    Història de HTTP






    • 1991: HTTP 0.9 – Primera versió desenvolupada per Tim Berners-Lee i l’equip del CERN.
    • 1996: HTTP 1.0 – RFC 1945.
    • 1997: HTTP 1.1 – RFC 2068, refinada amb RFC 2616 (1999).
    • 2015: HTTP 2.0 – RFC 7540, publicat el 14 de maig.
    • HTTP 3.0 (basat en QUIC): Millora el rendiment i seguretat de la web moderna.

    Avantatges

    • Independència de plataforma: Funciona a qualsevol sistema operatiu.
    • Compatibilitat: Integra amb múltiples protocols i tecnologies.
    • Eficiència: Optimitzat per al rendiment.
    • Seguretat: Suporta xifratge amb HTTPS per a transferències segures.

    Desavantatges

    • Manca de seguretat: Vulnerable a atacs man-in-the-middle si no es fa servir HTTPS.
    • Rendiment limitat: Pot ser lent per a grans volums de dades.
    • Sense estat: Requereix mecanismes addicionals (cookies, sessions, tokens) per mantenir l’estat.
