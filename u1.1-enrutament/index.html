    Teoria: Routing dins una LAN — Exemple Mikrotik 10.0.30.0/16

    Routing dins una LAN — Teoria i exemples amb MikroTik (Xarxa 10.0.30.0/16)

    Aquest document explica els conceptes bàsics del routing dins d'una LAN, com funciona el procés de lookup de rutes, i mostra exemples pràctics amb comandes de MikroTik. Tot l'exemple està ambientat a la xarxa 10.0.30.0/16.

    1. Introducció: routing vs switching

    En una LAN, els dispositius poden comunicar-se directament si estan al mateix domini de broadcast (mateixa subxarxa). El switch opera al nivell 2 (MAC), enviant trames dins el mateix VLAN/subxarxa. El router opera al nivell 3 (IP) i encamin a paquets entre subxarxes diferents.

    Per exemple, dues màquines a 10.0.30.10/16 i 10.0.30.20/16 no necessiten un router si comparteixen la mateixa subxarxa (p.ex. 10.0.30.0/24) i estan al mateix VLAN; però si estan en subxarxes diferents (10.0.30.0/24 i 10.0.31.0/24) cal un router o un L3 switch.

    2. Model d'exemple: toponomia

    Suposem aquesta topologia simplificada dins l'aula:

    Internet
   |
Router central (10.0.30.1)
   |
Switch d'aula (VLANs / ports)
   ├─ Grup A hosts (10.0.30.10–10.0.30.50)  <-- subnet 10.0.30.0/24
   ├─ Grup B hosts (10.0.31.10–10.0.31.50)  <-- subnet 10.0.31.0/24
   └─ MikroTik (com a L3 per una LAN específica) WAN:10.0.30.101 LAN:192.168.10.1

    En aquest document ens centrarem en l'ús d'un MikroTik connectat a la xarxa 10.0.30.0/16 amb la IP 10.0.30.101/16 a la interfície WAN (ether1) i una xarxa interna 192.168.10.0/24 a ether2.

    3. Adreçament i subxarxes

    La xarxa 10.0.30.0/16 cobreix adreces de 10.0.30.0 a 10.0.255.255. Però normalment en entorns d'aula es subdivideix en /24 per separar grups o VLANs.

    ObjecteIP / Subnet
    Router central10.0.30.1 /16
    MikroTik (WAN)10.0.30.101 /16
    MikroTik (LAN)192.168.10.1 /24
    Host dins LAN Mikrotik192.168.10.10 /24
    Nota: si el router central té rutes per defecte a Internet, el MikroTik pot fer NAT per al seu LAN, o pots afegir rutes de tornada perquè la xarxa 192.168.10.0/24 sigui accessible des de 10.0.30.0/16.

    4. Com funciona el procés de routing (lookup)

    Quan un router rep un paquet, segueix aquests passos simplificats:

    1. Comprova si la destinació és local (la IP està en una interfície pròpia o en una subxarxa connectada) → lliura localment.
    2. Si no és local, mira la taula de rutes per la ruta més específica (longest prefix match).
    3. Si troba una ruta, envia el paquet al següent salt (next-hop) indicat.
    4. Si no troba ruta, descarta el paquet o l'enquadra amb la ruta per defecte si existeix.

    Exemple de taula de rutes simple (MikroTik):

    /ip route print
Flags: X - disabled, D - dynamic, A - active, S - static
 0 A S 0.0.0.0/0 via 10.0.30.1
 1 A S 192.168.10.0/24  ether2
 2 A S 10.0.30.0/16  ether1

    La ruta 192.168.10.0/24 és més específica que 10.0.30.0/16; per tant, el router entregarà paquets a la LAN interna si la destinació és 192.168.10.X.

    5. Exemple pràctic: sortida a Internet per NAT

    Escenari: vols que els hosts de 192.168.10.0/24 sortin a Internet a través del router central 10.0.30.1. S'usen aquests passos al MikroTik:

    /ip address add address=10.0.30.101/16 interface=ether1 comment="WAN"
/ip address add address=192.168.10.1/24 interface=ether2 comment="LAN"
/ip route add dst-address=0.0.0.0/0 gateway=10.0.30.1
/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade

    Amb això, un host 192.168.10.10 amb gateway 192.168.10.1 podrà fer ping a 8.8.8.8. Si vols que des de la xarxa 10.0.30.0/16 (altres dispositius) pugui accedir a 192.168.10.10, cal afegir una ruta de tornada al router central:

    (al router central)  
/ip route add dst-address=192.168.10.0/24 gateway=10.0.30.101
    Si no afegeixes la ruta de tornada, el router central no sabrà com arribar a 192.168.10.0/24 i les connexions iniciades des d'allà fallaran.

    6. Exemple: rutes estàtiques entre subxarxes dins 10.0.30.0/16

    Suposa que tens dues subxarxes: 10.0.30.0/24 (VLAN 30) i 10.0.31.0/24 (VLAN 31) i un MikroTik que actua de router entre ambdues.

    /interface vlan add name=vlan30 interface=ether1 vlan-id=30
/ip address add address=10.0.30.1/24 interface=vlan30
/interface vlan add name=vlan31 interface=ether1 vlan-id=31
/ip address add address=10.0.31.1/24 interface=vlan31
/ip firewall filter add chain=forward src-address=10.0.30.0/24 dst-address=10.0.31.0/24 action=accept
/ip firewall filter add chain=forward src-address=10.0.31.0/24 dst-address=10.0.30.0/24 action=accept

    Aquestes comandes permeten que hosts de VLAN30 i VLAN31 es parlin mitjançant routing (L3) al Mikrotik.

    7. ARP i la resolució de capa 2

    Abans d'enviar un paquet al següent salt IP, el router necessita la direcció MAC del next-hop. Això s'aconsegueix mitjançant ARP (Address Resolution Protocol) en IPv4.

    /ip arp print

    Si el next-hop és 10.0.30.1, el Mikrotik mirarà ARP per a 10.0.30.1 i enviarà trames Ethernet a la MAC corresponent.

    8. Politíques de seguretat i filtres

    És recomanable controlar el trànsit entre subxarxes i cap a Internet amb regles firewall. Exemples bàsics:

    /ip firewall filter add chain=forward src-address=10.0.30.0/24 dst-address=192.168.10.0/24 action=accept
/ip firewall filter add chain=forward src-address=192.168.10.0/24 dst-address=10.0.30.0/16 action=accept
/ip firewall filter add chain=forward action=drop comment="block other forward"

    Accounts: les regles són processades per ordre. Col·loca regles accept abans d'una regla general de drop.

    9. Troubleshooting bàsic

    1. Verifica interfícies i IPs: /interface print i /ip address print.
    2. Comprova la taula de rutes: /ip route print.
    3. Assegura't que hi ha ARP del next-hop: /ip arp print.
    4. Prova amb ping al next-hop i a IPs externes: /ping 10.0.30.1, /ping 8.8.8.8.
    5. Comprova NAT i firewall: /ip firewall nat print, /ip firewall filter print.

    10. Resum i bones pràctiques

    • Segrega subxarxes amb VLANs per controlar dominis de broadcast i evitar conflictes (p.ex. DHCP).
    • Utilitza rutes estàtiques en laboratoris petits; en entorns més grans considera protocols dinàmics (OSPF).
    • Recorda afegir rutes de tornada als routers centrals quan afegeixis subxarxes privades.
    • Documenta IPs i topologia abans de la pràctica per evitar conflictes.
